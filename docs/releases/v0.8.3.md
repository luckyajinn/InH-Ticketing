# v0.8.3: Pre-pilot fixes: side panel, unsent replies, password check, signatures, odd characters

**Date:** 2026-11-10
**Built on:** `main`

Fixes from the review before the pilot: three independent reviews of v0.8.2
(security and privacy, feature logic, deployment and readiness) and an attack
test. None of the reviews found a way for staff to see anyone else's tickets,
notes or files; these are the issues a tester would trip over.

No screen looks different, so there are no new screenshots. The changes are
in what the pages do and in a few lines of wording.

## The side panel saves only what you changed

The side panel on a ticket (status, priority, assignee, category) used to send
all four values whenever one changed. If the page had been open a while and
someone else had changed the ticket since, saving put the old values back: it
could undo a colleague's assignment, or reopen a ticket the requester had just
marked as resolved.

Now the panel also sends what it showed when the page loaded, and saving
applies only the fields the person changed. Pages without JavaScript work the
same way.

## A reply you're typing is kept

Changing a side-panel field, or clicking **Assign to me**, reloads the page.
A reply or internal note being typed was lost. Now it's set aside just before
the page reloads and put back afterwards, still as a reply or a note, as it
was. It's kept only in that browser tab, and only until it's put back.

## Fewer false alarms from the password check

The check still leans towards warning, but it no longer warns on everyday
Mechanics and Cleaning & sanitization wording:

| No longer warns on | Why |
|---|---|
| "the pin is bent", "my pass is broken" | After "pin" or "pass", the value now needs a digit or a symbol |
| "lot code 23081", "batch code 7719", "cost code 4410", "part code 88-1204", order, job, asset and serial codes | Codes after these words are labels, not passwords |
| "2026-11-10 15:42:07Z" in a pasted sign-in error | Dates and times are skipped |

It now also catches lock combinations: "the combination is 12-34-56" and
"lock combo 2580".

## Signatures fold only when they look like one

Emailed tickets fold the sender's signature under **Show email signature**.
Two contact-looking lines at the end of an email (a list of rooms, units,
links or email addresses) used to fold too. Now the end of an email folds
only if it also has a name, a sign-off ("Thanks, Dana") or mail-app
boilerplate, and a `--` line only starts a signature near the end. CodeTwo
signatures fold as before (ticket #1071 in the demo data).

## No error pages from odd characters

A superscript digit ("²") passed the "is this a number?" check but then
failed as a number, so it showed an error page in six places: the
ticket-number box, the queue search and its filters, a follow-up link, and
common requests. These now treat it like any other text that isn't a number.

A signed-in person opening the sign-in page with an odd `next=` link also got
an error page; now they go to their home page. Only real page paths on this
site are followed.

## Wording for every team

The last places that read as if only IT uses the app: "Replies will appear
below", "Waiting for someone to pick it up", "Marked as resolved. Thanks for
letting us know.", and the receipt email ("We've got request #1042, and
someone will pick it up soon").

Also: when someone picks a common request and then chooses a different
category, their own choice now wins.

## The attack test

A new automated test (`tickets/tests/test_injection.py`) puts SQL injection,
shell command and template injection strings into every input: the New
request form, replies, internal notes, the password check, queue search and
filters, the side panel, the ticket-number box, sign-in links, admin search,
attachment file names and emails coming in. Each one is stored and shown as
plain text, exactly as typed; nothing runs, no table is touched, and no page
errors. With it, the suite is 283 tests, all passing.

## Docs

- **deployment.md:** `HELP_CONTACT` is in the `.env` template and the
  settings table, with a note to quote it if it contains `#`. Rolling back
  now has a way to keep tickets made since v0.7.0 (`migrate tickets 0003`
  first). The status banner says the server is in use.
- **restore.sh** prints the start command with `--build`, so a restore can't
  start a newer version's images on the restored database.
- **pilot-testing.md** is updated for v0.8.x, with checks for the new
  features, the side panel, unsent replies and odd characters.

## Upgrading

Follow [deployment.md](../deployment.md), section 10, with `v0.8.3`. No
database changes since v0.8.0. From v0.6.0 or v0.7.0, migrations `tickets`
0004 and 0005 run when the `web` container starts. Set `HELP_CONTACT` in the server's `.env`
first if it isn't set yet (in quotes if it contains `#`).

## Not in this version

Found by the reviews, planned before v1.0.0 ([backlog](../backlog.md),
v0.8.3):

- Protection for shared PCs: pages not cached after sign-out, and sign-in
  ending when the browser closes.
- The worker waiting for the web container's database updates on start-up.
- The tool to remove a pasted password from a ticket (v0.9.0).
