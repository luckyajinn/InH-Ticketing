# v0.10.2: An email when staff close a ticket

**Date:** 2026-11-11
**Built on:** `main`

A small change before v1.0.0: closing a ticket now tells the person who
raised it.

## The closed email

When an IT agent, a department agent or an admin sets a ticket to **Closed**
in the side panel, the requester gets an email:

> **Your request is closed and complete**
>
> Sam Patel closed #1001. It can't be changed now. If you need more help with
> it, open the request and choose "Start a follow-up".

It has the same `[#1001] Subject` as the ticket's other emails, so it joins
the same conversation in Outlook. With email-in on, its footer says that a
reply starts a new request linked to this one, which is what a reply to a
closed ticket already does.

What sends which email now:

| How the ticket ends | Email to the requester |
|---|---|
| Staff set it to Resolved, or click **Send and resolve** | "Resolved", with the date it closes by itself (unchanged) |
| Staff set it to Closed | **New:** "Closed and complete" |
| Staff resolve it, then close it | Both, one after the other |
| It closes by itself 7 days after being resolved | None (unchanged): the resolved email gave the date |
| The requester marks it resolved themselves | None (unchanged) |

As with every email, nobody gets one about their own action: an agent
closing a ticket they raised themselves gets nothing.

## Upgrading

Follow [deployment.md](../deployment.md), section 10, with `v0.10.2`. No
migrations, and nothing to do in `.env`. Rolling back to v0.10.1 is a
checkout and rebuild.
