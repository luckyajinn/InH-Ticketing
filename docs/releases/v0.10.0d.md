# v0.10.0d: Documentation update

**Date:** 2026-11-11
**Built on:** `main`

**Documentation only.** The app is exactly the same as [v0.10.0](v0.10.0.md):
no code, settings or database changes, and it still shows v0.10.0. The "d"
marks a documentation update.

**Installing v0.10.0?** Check out `v0.10.0d` instead. It's the same app, with
the notes and guides below, and v0.10.0's [Upgrading](v0.10.0.md#upgrading)
section still applies. Already on v0.10.0? Updating to v0.10.0d only changes
the documents on the server.

## What changed

### Installing v0.10.0

Its release notes now say, under **Before installing**, that the server's
`.env` must set `HELPDESK_HOSTNAME`. It no longer has a default, and the app
won't start without it. The `.env` in the deployment guide has always set it.

### The deployment guide

[deployment.md](../deployment.md):
- **New section 1.6, the network:**
  - the internal DNS record, on every network staff use
  - phones that skip the internal DNS (Android's Private DNS, iCloud Private
    Relay)
  - blocking the guest Wi-Fi
  - the internal root certificate on phones, through Intune or by hand
  - a phone check in the post-install list, and troubleshooting for a web
    host's page or a certificate warning on a phone
- **Updating:** set the version once (`NEW=…`) and run the rest as it is.
  Skipping versions is fine, after reading each skipped release's Upgrading
  section.
- **Changing a setting in `.env`:** `docker compose … up -d`, not `restart`.
- **Rolling back:** with the version written down before updating.
- **Restore drill:** the start command the script prints, and a warning for a
  server already in use.
- **New: restoring onto a new server** when the old one is lost.

### Usage rules

[usage-rules.md](../usage-rules.md) is drafted for Mechanics and Cleaning &
sanitization, **for the compliance lead's review**:
- a ticket asks for the work; the maintenance or cleaning record stays in the
  logbook or quality system
- internal notes are seen by the team working the ticket and by admins
- adding a department in the admin site needs the compliance lead's review first
- a Reviews table, to record the decision
