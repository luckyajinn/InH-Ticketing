# InH-Ticketing usage rules

**InH-Ticketing is for IT issues and requests only.** These rules come from
the system's intended-use and risk assessment, reviewed with Ruben Martinez.
McKenna Labs is FDA-regulated, and keeping the help desk to IT work is what
keeps it outside FDA record-keeping rules.

## Use it for

Anything you need from IT, for example:

- a laptop, monitor, printer or phone that isn't working
- installing or updating software
- Wi-Fi, VPN or internet problems
- sign-in, password or MFA problems
- equipment or accounts for a new starter

## Don't use it for

| Not for | Use instead |
|---|---|
| Product complaints, reactions or anything about product safety or quality | Tell **QA** directly |
| Changes to Deacom, laboratory or quality systems | The **change control** process (a ticket can quote the change number for the IT work) |
| Approving someone's access to Deacom or other regulated systems | The **formal access request** process (a ticket can quote the approval for the IT work) |
| Batch, production, laboratory or quality records | The relevant quality system |
| Customer or supplier communication | The usual business channels |

**Never put a password, PIN or recovery code in a ticket or screenshot.** IT
will never ask for one.

## For IT: when something out of scope arrives

| It's… | Do this |
|---|---|
| A product complaint or reaction report | **Forward it to QA the same day.** Reply to the person saying QA has it, then close the ticket with an internal note "Redirected to QA on <date>". **Never delete it.** |
| A request to change a regulated system | Ask for a change-control number; do the IT work only once it exists, and quote it in the ticket |
| A request for access to a regulated system | Check the approval exists in the formal access process; quote it in the ticket |
| A ticket containing a password | Reset that password straight away, and tell the person. The ticket's history shows **Possible password** when someone sent one anyway after the warning, or emailed one |
| Anything else that isn't IT | Point the person to the right team and close the ticket |

Internal notes are visible to IT only, but write them as you would any company
record: factual and professional.

## Changes to these rules

Any new use of InH-Ticketing must be reviewed with Ruben Martinez **before**
it starts, for example the planned extension to maintenance, and cleaning and
sanitization requests. Those are usually manufacturing-quality (GMP) records,
so they are likely to need extra controls. Review these rules once a year,
and whenever the use changes.
